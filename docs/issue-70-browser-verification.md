## 数据可用性审查修复证据

- 总览产生分析上下文时保留告警、设备、能耗三域状态。完整域返回真实零值时显示 `0`；`UNAVAILABLE` 携带默认零计数时显示“未取得”；`PARTIAL` 的正数显示“至少”，零值显示“总数未知”。
- 详情依据逐域处理状态：`PARTIAL` 保留已取得行并提示列表可能不完整；`UNAVAILABLE` 明确说明不能确认该域没有记录。提示在其他域仍有有效行时也保持可见。
- 2026-09-10 真实 Compose 数据中，创新中心能耗依据为 `PARTIAL`。浏览器显示“能耗依据仅部分可用”，同时保留告警、设备和计量点行；证据：`docs/evidence/issue-70/analysis-partial-evidence-1440x900.png`。
- 组件夹具覆盖不可用默认零、部分零/正数、空列表与其他域有效行组合；这些夹具只验证 UI 状态语义，不冒充真实接口状态。

## 加载、缺失、部分数据、失败与重试

- 组件交互测试覆盖：加载后正常完成、完整域真实零值、不可用域默认零、部分域正数/零值、依据空列表与有效行组合、接口失败后重试、快速从 B1 切换 B2 时丢弃旧响应、同楼宇同窗口可用性变化触发刷新，以及已完成响应的楼宇/窗口不一致时拒绝展示。
- 图表测试确认缺失点保持 `null` 断点，不连线、不补零；夜间高亮只按响应小时点的 22:00–06:00 生成。
- 真实浏览器中显式点击“运行 AI 分析”后，本地模型/分析链路返回失败。后端脱敏日志将失败定位为 `understandQuestion` 阶段的 `IllegalArgumentException`；当前证据不能继续断言是凭据、网络还是模型结构化输出中的哪一种具体原因。页面只显示客户可读的失败提示，保留全部已有业务事实和再次运行入口，没有泄漏内部运行编号、SQL 或 Trace。证据见 `analysis-ai-failure-1366x768.png`。
- AI 组件交互测试还覆盖重复点击抑制与澄清后继续；进入分析页本身不会自动调用模型。

因此，本次只能确认模型失败边界与重试入口正确，不能声称模型分析已成功。完成在线成功验收至少需要：在目标演示环境使用有效且获准的模型配置，从客户页真实点击启动一次新运行，后端最终状态为 `COMPLETED`，页面显示该次运行的“AI 分析结论”，且服务端无对应阶段失败。单测中的模拟完成状态不满足这些条件；模型在线成功仍属于部署环境验收。
