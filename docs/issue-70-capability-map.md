# Issue #70 运营分析页能力与字段映射

## 客户演示主线

`园区总览重点关注 / 当前楼宇 → 查看分析 → 结论与趋势 → 数据依据与建议 → 返回园区总览`

客户页面由 `ShowcaseHome` 保持同一个 `CustomerShell` 实例；顶部菜单、客户身份区和横幅容器始终由该 Shell 持有，运营分析只向同一横幅插入当前业务标题，不再创建页面级伪 Shell。运营分析不是内部技术工作台入口。返回总览时，`ParkOverview` 的显式楼宇偏好仍由原组件保存，并在重新取数后恢复。

## 跨页上下文

| 字段 | 来源 | 页面用途 |
| --- | --- | --- |
| `buildingId` / 中文楼宇名 | 首页楼宇目录与当前选择 | 标题、单楼宇查询、设备位置 |
| `anomalyId` | 当前楼宇证据中确实存在的首条告警；无告警则为 `null` | 后续人工确认的合法关联预留；本页不创建工单 |
| 异常标题 / 优先级 | 当前楼宇的告警、离线设备和能耗偏差事实 | 标题区与客户阅读顺序 |
| `overviewDomainStatus` | 产生首页摘要的告警、设备、能耗三域 `OK / PARTIAL / UNAVAILABLE` | 决定零值能否解释为确认零、部分值是否标为“至少/已观测”、不可用值是否显示“未取得” |
| `anomalyWindow` | `/api/operations/anomaly-overview` 的原始窗口 | 告警、设备、能耗证据；不与能耗图周期混用 |
| `energyWindow` | 首页从总览窗口确定并整点对齐的最近 24 小时窗口 | 单楼宇小时实际用电和基线查询 |
| 时区 | 后端窗口与时序响应的 `Asia/Shanghai` | 时间标注与 22:00–06:00 夜间高亮 |

分析页会拒绝楼宇、指标、窗口、粒度或时区与当前上下文不一致的已完成响应；快速切换以请求 generation 隔离旧响应。

## 数据与动作映射

| 页面内容 / 动作 | 实现级别 | 真实来源与边界 |
| --- | --- | --- |
| 规则化运营观察 | `DIRECT_REUSE` | 异常总览楼宇摘要及三域可用性；只有 `OK` 的零值显示为确认零，`PARTIAL` 使用部分口径，`UNAVAILABLE` 显示未取得；明确标注未调用模型 |
| AI 分析 | `ADAPTED` | 用户显式点击后复用现有 `useOperationsAnalysis` 受控只读链路；等待、澄清、完成、失败均保留，不显示内部运行编号或技术执行细节 |
| 实际用电曲线 | `DIRECT_REUSE` | `energy_kwh`，单楼宇、继承的小时窗口；缺失点为断点，不补零 |
| 基线曲线 | `ADAPTED` | 在既有 `MetricCatalog` 和同一受治理时序服务中新增 `energy_baseline_kwh = SUM(baseline_kwh)`；没有新 SQL 接口，也不在前端倒算基线 |
| 夜间高亮 | `ADAPTED` | 只在小时粒度上按响应时区判断 22:00–06:00；不是单独的夜间统计结论 |
| 可能原因 | `ADAPTED` | 仅把能耗偏差、离线设备和告警类别写成“待核查线索”，不声称故障已确认 |
| 建议措施 | `ADAPTED` | 人工核对、恢复采集、持续观察；页面不执行能源控制 |
| 相关设备与记录 | `DIRECT_REUSE` | `/api/operations/anomaly-evidence/{buildingId}` 的告警设备、离线设备与计量点；逐域显示 `PARTIAL / UNAVAILABLE`，保留已取得行，只有相关域全部 `OK` 且为空时才声明暂无记录 |
| 进入人工确认 | `NOT_READY` | #71 尚未交付；按钮保留但禁用，不创建工单、不绕过审批 |
| 加入简报 | `NOT_READY` | 当前报告契约不支持自选内容；不提供假成功动作 |

## 与设计稿的事实差异

- 不采用图片中的“2号办公楼”、固定日期、121%、2,480 kWh、连续 3 天等示例值；页面只显示当前接口返回的楼宇、周期和数值。
- 设计稿七天曲线改为首页已实际查询并传递的最近 24 小时整点窗口，避免进入详情后重新按当前时间计算。
- 基线是单条虚线，不绘制无契约的“正常范围”；基线不可用时只展示实际用电和明确说明。
- 设备表不补造设备名称、位置楼层、日用电或运行状态；只展示合法关联字段。
- “生成工单”和“加入简报”未伪装成功；分别等待 #71 和支持自选内容的报告契约。

## 验证边界

- 组件回归覆盖正常、空/不可用、部分数据、失败与重试、快速切换、慢证据请求下立即导航且不重复请求、错误范围响应、AI 显式启动/重复点击和澄清。
- 浏览器证据必须注明实际运行的 Compose analytics 演示栈和模型状态。若模型未配置，只能证明失败边界与既有事实可继续阅读，不能声称模型分析成功。
