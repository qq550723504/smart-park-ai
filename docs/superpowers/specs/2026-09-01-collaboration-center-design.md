# 统一协同中心只读版设计

## 1. 目标

把方案页中的“AI 智能工单与跨部门协同”落成一个可演示、可审计的工作台入口，先统一展示现有告警处置流程和客服人工工单，不新增模型决策或自动写操作。用户可以从一个队列看到待人工审批、处理中、失败和已完成的工作项，并跳回原有场景继续处理。

## 2. 当前缺口与边界

当前告警处置使用 `WorkflowSnapshot` / `WorkOrder`，客服使用 `CustomerTicket`，两者状态机、权限和写接口不同。协同中心不得把它们强行合并成一个领域对象；新增的是应用层只读投影 `CollaborationWorkItem`，保留来源类型和原始标识，避免破坏现有工作流与客服契约。

本批不包含：自动派单、自动审批、设备控制、客服工单状态机改造、专家协作写入、持久化改造、生产认证和跨租户权限。

## 3. 方案

### 3.1 应用层查询服务

新增 `CollaborationCenterService`，依赖 `WorkflowExecutionStore` 与 `CustomerTicketPort`，负责读取两个来源并转换成安全投影。查询结果按更新时间倒序，默认限制数量，服务层过滤无法公开的原始诊断、审批评论、知识正文和个人信息。

建议的投影字段：

- `id`：来源前缀加原始 ID，避免跨来源冲突
- `source`：`ALERT_WORKFLOW` 或 `CUSTOMER_TICKET`
- `status`：来源状态的稳定展示枚举
- `priority`：告警风险映射为 `HIGH|NORMAL`，客服工单默认 `NORMAL`
- `title`、`safeSummary`：受控摘要，不返回自由文本原文
- `parkId`、`buildingId`、`deviceId`：仅告警来源且已有公开字段时返回
- `updatedAt`
- `detailPath`：前端已有场景的内部跳转目标

### 3.2 REST 接口

新增 `GET /api/collaboration/work-items`。

- 需要 `CUSTOMER_AGENT` 或 `ADMIN` 演示角色；未授权返回现有统一权限错误。
- 支持可选 `source`、`status`、`limit` 查询参数；服务端白名单解析，非法值返回 400。
- 只读，无副作用；响应为稳定 DTO 数组，不暴露领域对象。
- 默认最多返回 50 条，避免进程内存储被无界读取。

### 3.3 前端协同中心

在运营工作台新增“协同中心”导航和页面，页面包含：

- 顶部聚合：全部、待审批、处理中、需关注数量
- 来源与状态筛选
- 工作项列表：来源、风险/优先级、摘要、更新时间、状态
- “打开原场景”按钮：告警跳到告警工作流，客服跳到客服控制台
- 空态和无权限态；不显示静态伪造数据

页面只调用新增只读接口，不复制告警或客服的状态推进逻辑。现有场景页面仍是唯一写操作入口。

## 4. 数据与安全规则

- 告警项只能使用 `WorkflowSnapshot` 的公开标识、风险级别、状态和受控摘要。
- 客服项只能使用 `CustomerTicket` 的 ID、状态、意图和 `safeSummary`。
- 不返回审批人、审批意见、诊断正文、知识正文、原始工具结果、人员身份或敏感标识。
- 服务层对状态和来源做显式枚举映射，未知值 fail closed，不透传字符串。
- 读取两个来源失败时返回安全错误，不用空数组伪装“没有工作项”。

## 5. 测试与验收

后端：

- 应用层投影覆盖告警、客服、空队列和状态映射。
- Controller 覆盖角色门禁、参数白名单、默认上限和字段脱敏。
- 现有告警/客服测试全部保持通过。

前端：

- 组件测试覆盖列表、筛选、空态、无权限态和内部跳转。
- 工作台导航在能力可用时显示，在接口失败时不显示伪造队列。
- 类型检查、单元测试和生产构建通过。

浏览器验收：

1. 管理员进入协同中心看到真实队列或明确空态。
2. 过滤来源和状态后列表数量与接口一致。
3. 点击告警/客服工作项能进入对应现有页面。
4. 普通查看者看不到协同中心的受限数据。

## 6. 后续扩展

待只读投影稳定后，再单独评审 SLA 计算、统一事件流、人工确认动作和持久化。任何写操作必须继续复用现有审批、幂等和审计边界，不在本批预留“万能协同 API”。
