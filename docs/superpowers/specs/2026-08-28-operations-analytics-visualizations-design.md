# 运营分析全套展示与模拟数据设计

日期：2026-08-28

## 目标

在现有运营分析的真实只读查询、结果表和 SSE 图表事件基础上，补齐一套可由查询结果驱动的展示方式，并增加足够的确定性模拟数据，使以下场景可以真实查询和展示：楼宇能耗对比、能耗趋势、能耗构成、时段热度、目标完成率、能耗与运营负载关系、楼宇空间分布。

## 范围

第一期一次交付以下展示类型：

- `KPI`：总量、平均值、最大值或目标完成率等指标卡。
- `BAR`：普通柱状图；支持横向排行。
- `STACKED_BAR`：按第二维度展示构成。
- `LINE`：时间趋势。
- `HEATMAP`：二维维度热度矩阵。
- `CALENDAR_HEATMAP`：按日期展示连续时间热度。
- `SCATTER`：两个数值字段之间的关系。
- `GAUGE`：目标完成率或阈值使用率。
- `MAP`：基于楼宇演示坐标的空间分布散点图，不伪装成真实地理地图。
- `TABLE`：所有图表不适用或校验失败时的安全兜底。

不在本期范围：外部地图瓦片、真实 GIS 路网、楼层 CAD/图片底图、自动推断面积或目标值。没有对应数据时必须回退表格并明确原因。

## 数据与查询模型

新增一个数据库迁移，补充以下模拟数据边界：

- 楼宇画像：楼宇名称、面积、楼层数、演示坐标、日能耗目标。
- 小时运营负载：楼宇每小时占用人数，用于散点图和负载对比。
- 能耗目标字段：用于目标完成率和仪表盘，目标值进入只读结果或由指标目录固定定义，不能由模型填写。
- 扩充能耗视图的派生列：楼宇名称、日期、小时、星期、面积、坐标、占用人数和目标值。

指标目录新增或完善：

- 能耗、峰值功率、平均占用人数、目标完成率。
- 允许按楼宇、楼宇名称、日期、小时、星期、表计、设备/构成维度进行分组。

数据库仍只向分析只读角色开放白名单视图；原始画像和负载表不直接授权。所有新增数据固定为演示数据，并以当前日期为锚点，保证“过去 N 天”查询在不同运行日期都能命中。

## 图表契约

扩展后端 `ChartSpec`、执行事件 `ChartPayload` 和前端 `DisplayPayload`，保持字段来源可审计：

- `type` 使用上述有限枚举。
- `xField`、`yFields`、`seriesField` 必须来自已执行结果列。
- `unit` 必须来自指标目录；多单位混图回退表格。
- 增加受控的方向、堆叠、目标值和空间坐标配置；这些配置由服务端根据查询计划和结果推导，模型只能提出候选。
- 服务器校验数值列、二维维度、重复坐标、基数和空结果；不满足条件时回退 `TABLE`，不得生成虚假数据。
- 保留现有 `CHART_SPECIFIED` SSE 事件，前端从事件接收图表规格，状态接口继续只承载结果表和运行状态。

图表选择规则：

- 明确的时间维度优先 `LINE` 或 `CALENDAR_HEATMAP`。
- 单一分类对比优先 `BAR`，楼宇名称较长时使用横向方向。
- 存在系列维度时使用 `STACKED_BAR`。
- 两个离散维度加一个数值指标使用 `HEATMAP`。
- 两个数值字段使用 `SCATTER`。
- 单值目标/比例使用 `KPI` 或 `GAUGE`。
- 结果包含坐标和楼宇维度时才允许 `MAP`。
- 其他情况使用 `TABLE`。

## 前端实现

继续复用现有 Apache ECharts，不自行实现图表引擎。`AnalyticsChart` 根据后端类型渲染：

- 卡片和仪表盘使用可访问的文本值作为补充；
- 热力图、日历热力图、散点图和空间分布图使用真实结果行；
- 横向排行和堆叠柱状图复用柱状图配置；
- 结果表始终保留，保证图表渲染失败时仍可审计数据。

提示问题增加覆盖这些场景的示例，至少包括：过去 5 天各楼宇能耗、按小时能耗趋势、楼宇能耗排行、楼宇能耗热力图、能耗目标完成率和能耗与占用人数关系。

## 错误与安全

- 模型提出未知图表类型、未知字段或不匹配维度时，服务端回退表格并记录安全失败阶段。
- 空结果、单点趋势、过高基数、混合单位和缺失坐标不强行绘图。
- SQL 仍由已校验 `QueryPlan` 参数化渲染，并继续经过 AST、计划、只读角色和成本门禁。
- 不向事件、API 或日志输出原始模型响应、数据库凭据或供应商错误正文。

## 验证

- Java：图表契约、每类图表的字段/类型/单位校验、表格回退、多指标和新增视图迁移测试。
- Vue：每种图表类型至少一个渲染/降级测试，提示问题点击测试，以及真实结果行不被前端改写的测试。
- 运行时：使用 Compose 分析配置验证新增迁移、能力接口、至少六类查询结果和对应 `CHART_SPECIFIED` 事件；服务健康检查和只读权限测试继续通过。
