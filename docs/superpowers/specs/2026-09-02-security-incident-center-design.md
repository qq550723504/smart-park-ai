# 安全事件研判中心设计

## 1. 目标

在现有安全事件、告警工作流和协同中心之上，增加一个面向 `APPROVER` 与 `ADMIN` 的“安全事件研判”演示切片。该切片将多个脱敏安全事件和关联告警归并为可解释的事件实例，展示风险、时间线、证据摘要和下一步建议，并在需要人工处置时转入现有协同工作项与审批链。

首版服务于方案页中的“AI 安全运营与事件研判中心”场景，但保持会话级、只读优先的演示边界：数据来自现有 Mock 适配器和安全端口，不接入原始视频、身份信息、真实门禁/摄像头适配器或新的设备控制、通知通道。

## 2. 范围与非目标

### 2.1 本次范围

- 新增独立的 `SecurityIncident` 领域模型、归并服务和安全 DTO。
- 复用现有 `SecurityPort`、`AlertPort`、告警工作流、协同中心和审批链，不复制其写入逻辑。
- 按同园区、同区域（当前由 `buildingId` 表示）、同事件类型且时间差不超过 15 分钟的确定性规则归并事件。
- 提供安全事件列表、事件详情时间线、关联告警和脱敏证据摘要。
- 提供“标记已研判”和“转为协同工作项”两个动作；转出后继续使用现有协同中心和审批能力。
- 在运营工作台增加独立“安全事件研判”视图，并提供空态、权限态、失败态和跳转协同反馈。
- 增加归并边界、脱敏、权限、动作幂等和前端交互测试。

### 2.2 非目标

- 不接收或返回原始视频、图片、音频、人脸特征、证件原文或其他身份信息。
- 不引入模型推理、向量检索、事件总线、规则配置平台或新的持久化数据库。
- 不在研判页直接关闭告警、派单、发送通知、控制设备或批准高风险动作。
- 不修改 `CollaborationCenterService` 的事件归并职责；协同中心只管理已转出的工作项。
- 不向 `CUSTOMER_AGENT` 暴露安全事件列表或证据详情；该角色只查看已转出的客服可见工作项。
- 不把进程内 Mock 归并结果包装为生产级历史事件库或 SLA 承诺。

## 3. 架构

### 3.1 分层与依赖

```text
SecurityPort + AlertPort
          ↓
SecurityIncidentService
  ├─ 读取并归并脱敏事件
  ├─ 组装风险、证据和时间线
  └─ 调用受控的协同转出端口
          ↓
SecurityIncidentController
          ↓
安全事件研判页面
          ↓
现有 CollaborationCenter / Approval 链
```

归并逻辑位于安全事件应用/领域包，不放在 Controller、前端或协同中心中。服务只依赖端口和安全投影，不能直接依赖 Mock 适配器、数据库实现或设备控制适配器。

### 3.2 领域模型

`SecurityIncident` 为不可变模型，至少包含：

| 字段 | 说明 |
| --- | --- |
| `incidentId` | 服务端生成的稳定 ID |
| `parkId` / `buildingId` | 园区与区域标识 |
| `eventType` | 归并使用的稳定事件类型 |
| `riskLevel` | `LOW`、`MEDIUM`、`HIGH` |
| `status` | `OPEN`、`REVIEWED`、`HANDOFF` |
| `openedAt` / `lastOccurredAt` | 事件首末发生时间 |
| `eventIds` | 关联安全事件 ID，稳定排序 |
| `alertIds` | 关联告警 ID，稳定排序 |
| `evidence` | 脱敏证据摘要列表 |
| `timeline` | 按时间排序的事件/告警节点 |
| `recommendations` | 固定模板生成的建议，不包含模型原文 |
| `reviewedAt` / `handoffWorkItemId` | 动作完成后的安全元数据 |

模型构造沿用 `SecurityEvent` 的强制脱敏校验；任何证据摘要必须以 `REDACTED:` 开头，并受长度和原始载荷标记检查约束。响应 DTO 只允许上述白名单字段。

### 3.3 确定性归并规则

1. 读取当前安全事件及关联告警的有限集合。
2. 按 `parkId + buildingId + eventType` 分桶。
3. 每个桶内按 `occurredAt` 升序遍历；相邻事件时间差不超过 15 分钟时放入同一事件实例，否则开启新实例。
4. 告警通过已有告警与事件关联信息加入事件；无法安全关联的告警不强行拼接。
5. `incidentId` 根据稳定的分组键和首个事件 ID 生成，避免同一会话刷新产生随机重复事件。
6. 风险等级使用现有告警风险映射：存在高风险告警则为 `HIGH`，否则沿用最高安全事件风险；没有风险信息时为 `MEDIUM`，不编造数值。
7. 列表按 `riskLevel` 降序、`lastOccurredAt` 降序、`incidentId` 升序排列；详情内事件、告警和时间线均稳定排序。

规则边界必须覆盖：15 分钟内归并、超过 15 分钟拆分、不同区域拆分、不同事件类型拆分、乱序输入仍得到同一结果。

## 4. REST 契约

### 4.1 查询事件列表

`GET /api/security/incidents?status=OPEN&limit=20`

- 需要请求头 `X-Demo-Role: APPROVER` 或 `ADMIN`；缺少或不允许的角色使用现有安全错误语义。
- `status` 仅允许 `OPEN`、`REVIEWED`、`HANDOFF`；`limit` 为有限正整数并有服务端上限。
- 返回只读安全投影：

```json
{
  "items": [
    {
      "incidentId": "INC-ACCESS-001",
      "parkId": "PARK-A",
      "buildingId": "B1",
      "eventType": "UNAUTHORIZED_ACCESS",
      "riskLevel": "HIGH",
      "status": "OPEN",
      "openedAt": "2026-09-02T08:00:00Z",
      "lastOccurredAt": "2026-09-02T08:09:00Z",
      "eventCount": 2,
      "alertCount": 1,
      "summary": "REDACTED:同一区域在短时间内出现多次未授权访问迹象"
    }
  ],
  "total": 1
}
```

### 4.2 查询事件详情

`GET /api/security/incidents/{incidentId}`

- 使用同样的角色要求和资源不存在语义。
- 返回完整白名单投影，包括关联 ID、脱敏证据、时间线和建议；不返回原始请求、模型 Prompt、供应商响应或异常堆栈。

### 4.3 标记已研判

`POST /api/security/incidents/{incidentId}/review`

- 仅 `APPROVER`、`ADMIN` 可调用；空对象请求体，不接受客户端状态覆盖。
- `OPEN` 转为 `REVIEWED`；重复调用为幂等成功并返回当前事件。
- 记录现有审计轨迹，失败时不改变状态。

### 4.4 转为协同工作项

`POST /api/security/incidents/{incidentId}/handoff`

- 仅 `APPROVER`、`ADMIN` 可调用；服务端使用固定标题、风险和脱敏摘要生成协同请求。
- 首次调用创建或复用一个协同工作项并将状态转为 `HANDOFF`；重复调用返回同一个 `handoffWorkItemId`，不得重复建单。
- 协同请求沿用现有安全审批/审计边界，不直接执行通知、派单或设备控制。

## 5. 前端交互

在 `OperationsWorkbench` 增加“安全事件研判”导航项，仅对 `APPROVER`、`ADMIN` 显示。页面包含：

- 顶部统计：未研判、高风险、已转协同数量；没有数据时显示明确空态，不显示静态默认数字。
- 左侧事件列表：风险、状态、区域、事件类型、首末时间、事件/告警数量。
- 右侧详情：事件摘要、风险标签、关联 ID、脱敏证据卡片、时间线、固定建议。
- 操作区：`标记已研判`、`转为协同工作项`；已完成动作显示幂等结果和目标工作项 ID。
- 转协同成功后提供跳转协同中心入口，不复制协同详情；权限不足、资源不存在、网络错误和动作冲突分别给出可理解的提示。
- 请求采用请求代次或取消机制，防止切换事件、刷新列表和角色切换时旧响应覆盖新状态。

## 6. 安全与失败处理

- Controller 执行角色校验，应用服务不信任客户端传入的角色字段。
- 所有公开文本使用固定模板或已校验的脱敏摘要；禁止前端自行拼接原始证据。
- 归并输入为空时返回空列表；单条坏数据被拒绝并记录安全阶段，不以默认事件补位。
- 读取端口失败返回受控能力错误，不泄露适配器异常信息。
- 标记和转协同动作使用状态条件或稳定幂等键，避免并发重复建单。
- 进程内结果和事件轨迹采用有限保留；服务重启后不承诺历史事件仍存在。

## 7. 测试与验收

### 7.1 后端

- 领域模型拒绝未脱敏、超长或包含原始载荷标记的证据。
- 归并服务覆盖 15 分钟边界、分桶边界、乱序输入、稳定 ID 和稳定排序。
- 风险映射、空结果、端口异常和坏数据均有明确测试。
- Controller 覆盖 `APPROVER`/`ADMIN` 允许，`VIEWER`/`OPERATOR`/`CUSTOMER_AGENT` 拒绝；列表、详情、未知资源和参数错误符合现有错误契约。
- review 与 handoff 覆盖状态迁移、重复调用幂等、并发冲突、审计事件和不重复建单。
- DTO 白名单测试确保无 SQL、Prompt、供应商响应、凭据、原始媒体和身份字段。

### 7.2 前端

- 角色控制正确显示导航和操作按钮。
- 列表、详情、空态、加载态、错误态和状态刷新正确呈现。
- 事件切换和刷新不会被旧响应覆盖。
- 标记已研判与转协同成功后状态和跳转入口正确；重复点击不会产生重复工作项。
- 页面只消费后端风险、时间线和摘要，不在前端推导事件归并或风险等级。

### 7.3 验收边界

- 默认离线 Mock 模式能展示真实的脱敏安全事件归并结果。
- 研判过程可追溯到事件 ID、告警 ID、时间线和协同工作项 ID。
- 任何高风险处置仍需进入现有审批链；研判页面没有直接控制设备或发送通知的能力。
- 文档明确标注这是会话级演示能力，生产化需要独立持久化、事件接入、审计保留和权限评审。
