# 运营日报会话快照设计

## 1. 目标

在现有运营分析和运营看板之上，增加一个可手动触发的“运营日报”演示切片。日报将固定编排三类已经存在的只读分析：能耗基线偏差、停车利用率和告警风险。每个章节都必须来自真实的运营分析结果，并保留指标口径、时间范围、摘要和结果表，使客户能够看到从数据查询到管理摘要的可追溯链路。

本切片服务于方案页中的“AI运营驾驶舱与自动报告”P0 场景，但只实现会话级手动生成，不把演示能力包装成生产调度系统。

## 2. 范围与非目标

### 2.1 本次范围

- 在应用层增加日报编排服务和有界的进程内报告存储。
- 通过固定模板顺序执行三个现有运营分析问题。
- 使用现有运营分析的时间解析、指标目录、SQL AST 安全校验、成本门禁、只读执行、摘要校验和结果脱敏链路。
- 增加报告级 REST API 和报告级统一执行事件。
- 在运营看板增加生成入口、整体状态和章节级结果展示。
- 增加角色、并发、失败隔离、空结果和敏感字段测试，并更新客户能力和架构文档。

### 2.2 非目标

- 不新增 SQL 生成器、报表数据库、定时任务、消息推送或邮件发送。
- 不允许客户端提交任意 SQL、任意报告问题或绕过指标目录。
- 不自动创建工单、派单、审批、通知或控制设备。
- 不把章节分析结果写入现有业务会话、工单或告警状态。
- 不为缺失数据生成默认数字、趋势或结论。
- 不把会话快照称为生产日报、历史报表或 SLA 承诺。

## 3. 架构

### 3.1 报告定义

在 `analytics` 应用层定义不可变的 `OperationsReportDefinition` 和固定章节列表。每个章节包含稳定 ID、中文标题和服务端固定问题：

| 章节 ID | 标题 | 固定问题 |
| --- | --- | --- |
| `ENERGY_BASELINE` | 能耗基线偏差 | `过去5天各楼宇能耗基线偏差` |
| `PARKING_UTILIZATION` | 停车利用率 | `过去5天各停车区域停车利用率` |
| `ALERT_RISK` | 告警风险 | `过去5天高风险告警数量` |

固定问题必须能够通过现有 `MetricCatalog` 和时间意图规则解析。若未来调整问题，必须同步更新定义测试，不从 HTTP 请求读取问题文本。

### 3.2 章节执行边界

`OperationsDailyReportService` 负责报告生命周期，不复制分析图或 SQL 逻辑。它通过一个应用层章节执行端口调用现有 `OperationsAnalysisService` 的受控内部执行入口；该入口复用现有的单运行并发限制、超时、分析事件和 `AnalysisRunStore` 结果投影。报告服务按固定顺序执行章节，前一章节终态后才开始下一章节，避免突破分析服务的资源边界。

章节执行端口只返回安全的 `RunRecord` 投影。报告服务将其映射为章节 DTO，允许摘要、行数、截断标记、时间解析元数据、白名单列和结果行，禁止携带 SQL、Prompt、供应商响应、凭据或未经校验的自由文本。

### 3.3 报告存储与生命周期

新增线程安全的进程内报告存储：

- 只保存最近的有限数量报告和受限结果行，超过上限淘汰最旧终态报告。
- 报告初始状态为 `RUNNING`，全部章节成功后为 `COMPLETED`，部分章节成功为 `PARTIAL`，全部章节失败或报告级异常为 `FAILED`。
- 服务重启后报告消失；接口和前端明确标注“本次会话”。
- 同一进程只允许一个报告编排运行；已有报告运行时返回受控冲突错误，不排队、不覆盖旧报告。

## 4. REST 契约

### 4.1 创建报告

`POST /api/operations-reports/runs`

- 请求体必须为空对象；出现未知字段返回参数错误，且任何请求字段都不能改变固定模板。
- 需要 `X-Demo-Role: OPERATOR` 或 `ADMIN`。
- 分析能力未启用时由现有条件装配保持接口不可用或返回受控能力错误，不伪造报告。
- 成功返回 HTTP `202`：

```json
{
  "runId": "uuid",
  "statusUrl": "/api/operations-reports/runs/uuid"
}
```

### 4.2 查询报告

`GET /api/operations-reports/runs/{runId}`

- 需要 `OPERATOR` 或 `ADMIN`。
- 未知或已过期的 `runId` 返回现有安全的资源不存在错误。
- 返回结构：

```json
{
  "runId": "uuid",
  "status": "RUNNING|COMPLETED|PARTIAL|FAILED",
  "createdAt": "2026-09-02T10:00:00Z",
  "updatedAt": "2026-09-02T10:00:03Z",
  "sections": [
    {
      "id": "ENERGY_BASELINE",
      "title": "能耗基线偏差",
      "question": "过去5天各楼宇能耗基线偏差",
      "status": "PENDING|RUNNING|COMPLETED|FAILED",
      "summary": "安全摘要或空字符串",
      "rowCount": 2,
      "truncated": false,
      "columns": ["building_name", "energy_deviation_pct"],
      "rows": [["A1", 3.2]],
      "timeResolution": {},
      "failureStage": null
    }
  ]
}
```

结果行沿用分析链路的安全投影和有限行数；服务端不得把原始 SQL 或模型输出放入报告 DTO。章节失败时 `summary`、`columns` 和 `rows` 为空，`failureStage` 使用稳定阶段标识。

## 5. 统一执行事件

报告使用独立的报告级 `runId`，通过现有 `ExecutionEventPublisher` 发布：

1. `RUN_STARTED` / `INITIALIZATION`：运营日报开始。
2. 每个章节发布 `NODE_STARTED` / `ANALYSIS`，摘要只包含固定章节标题。
3. 章节完成发布 `NODE_COMPLETED` / `ANALYSIS`；章节失败也使用 `NODE_COMPLETED` / `ANALYSIS` 搭配 `FAILED` 状态表示该章节终止，但不关闭报告级事件流，且不能泄露异常文本。
4. 报告终态发布 `COMPLETED` 或 `FAILED`。`PARTIAL` 报告使用完成事件，但安全摘要明确说明存在失败章节。

章节内部的分析 run 仍由现有分析服务发布其自身事件；报告轨迹只作为编排层摘要，不把内部事件任意重写为报告字段。前端继续使用现有 `ExecutionTraceRail` 订阅报告级 runId。

## 6. 前端交互

`OperationsBoard` 增加“生成运营日报”按钮，仅在当前运营分析能力可用且角色为 `OPERATOR` 或 `ADMIN` 时启用。点击后：

1. 调用创建接口，接受 `runId` 后立即订阅报告级执行轨迹。
2. 轮询报告状态直到终态，使用请求代次防止旧报告覆盖新报告。
3. 报告面板展示“本次会话运营日报”标题、整体状态和三个章节卡片。
4. 章节卡片分别展示等待、执行中、完成或失败状态；完成时展示安全摘要、时间范围和结果表。
5. `PARTIAL` 状态保留成功章节并在顶部提示失败章节；失败只允许重试整份报告，不自动重复单个章节。
6. 切换页面或返回首页时停止轮询，已有报告结果保留在当前工作台实例中；重新生成前显式替换旧报告。

没有报告时显示说明文字而不是静态指标。能力错误、权限错误、并发冲突和网络失败分别显示可重试提示，不清空已有成功报告。

## 7. 安全与失败处理

- 角色校验位于 Controller，应用服务不信任客户端传入的角色或章节。
- 报告服务不能调用写端口；架构测试禁止报告包依赖工单、审批或设备控制适配器。
- 章节执行返回 `NEEDS_CLARIFICATION` 时，固定问题契约视为失败并记录稳定阶段 `REPORT_CLARIFICATION_REQUIRED`，不把交互式澄清暴露成报告输入。
- 章节没有数据时保留后端的明确空结果语义，章节可完成但不生成推断性摘要。
- 任何异常只记录安全阶段和异常类型，公开 DTO 使用固定错误码或阶段名。
- 报告结果和执行事件都受进程内有界保留约束，不能无界累积大结果表。

## 8. 测试与验收

### 8.1 后端

- 报告定义包含且只包含三个固定章节，问题文本与指标目录可解析。
- 存储覆盖并发创建、状态迁移、终态保留上限、过期和不可变返回值。
- 服务覆盖顺序执行、全部成功、部分失败、全部失败、空结果、超时和分析能力错误。
- Controller 覆盖 `OPERATOR`/`ADMIN` 允许，`VIEWER`/`CUSTOMER_AGENT` 拒绝，未知报告和并发冲突。
- DTO 白名单测试断言没有 SQL、Prompt、供应商响应、凭据、原始异常或写操作字段。
- 执行事件测试覆盖报告级 runId、顺序、终态和安全摘要。

### 8.2 前端

- 看板按角色显示或隐藏生成入口。
- 创建成功后订阅并轮询，终态正确展示三章节。
- 部分失败保留成功章节，全部失败不显示默认数字。
- 请求失败、并发冲突、切换页面和重新生成不会发生旧响应覆盖。
- 结果表和时间范围只使用后端 DTO，不在前端推导指标或结论。

### 8.3 验收边界

- 默认离线模式不显示伪造日报；分析能力未启用时明确提示不可用。
- 具备分析链路时，手动生成报告能够看到真实查询结果或明确空结果。
- 右侧轨迹栏显示报告编排过程，且不暴露 SQL、Prompt、模型原文或敏感数据。
- 文档明确说明这是会话级演示快照，生产化需要单独设计持久化、调度、权限和通知。
