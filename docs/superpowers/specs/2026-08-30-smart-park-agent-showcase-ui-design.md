# 智慧园区 Agent 客户体验导览 UI 设计

## 1. 文档状态

- 日期：2026-08-30
- 状态：已完成规格，等待用户评审
- 适用项目：`springaialibaba` 智慧园区演示应用
- 设计方向：证据剧场（Evidence Theater）

本规格将当前以功能标签为中心的运营工作台，升级为面向企业客户的 Agent 能力体验导览；同时保留原有工作台给操作人员使用。目标不是用视觉包装未验证的能力，而是让客户在约一分钟内看见真实任务、真实 Agent 分工、真实证据与人工决策边界。

## 2. 问题与目标

### 2.1 当前问题

当前 `App.vue` 将告警工作流、客服、实时语音、专家协作和运营分析并列为场景标签。主视图第一屏需要用户理解告警收件箱、工作流图、实时事件、运营指标和故障注入器等大量操作性元素，适合内部学习与调试，不适合面向客户讲清 Agent 的业务价值。

此外，前端只根据 `analyticsEnabled`、`collaborationEnabled` 和 `voiceEnabled` 决定是否显示场景。它不能表达某场景是否已完成在线链路检查、使用的是何种真实数据、为何不可用，以及哪些人工边界仍然存在。客户看见的“模拟园区系统”与隐藏的能力入口，会把产品叙事从可信的 Agent 演示拉回不确定的技术样例。

### 2.2 目标

1. 在 60 秒内完成一次可理解的客户演示：发现问题、Agent 推理、证据汇聚、人工把关和可追溯结果。
2. 把“真实可运行”而不是“功能数量”作为第一层信息；场景只有通过对应在线能力检查后才可启动。
3. 让每个结论都能回到安全事件、工具查询、结构化 Finding、只读 SQL 结果或人工审批，而不展示思维链、原始 Prompt、密钥或脱敏前数据。
4. 保留现有告警、客服、分析和协作页面的工作能力，避免复制业务编排或重写后端契约。
5. 在大屏桌面演示和常规桌面浏览器中都保持清晰、可访问、可中断的体验。

### 2.3 非目标

- 不把 Mock、预录结果、前端计时动画或静态样例伪装为实时 Agent 执行。
- 不把语音、跨域协作或运营分析当作默认可售能力；其可见性必须由当前运行能力和健康检查决定。
- 不引入设备控制、自动工单批准、人员身份推断或其他高风险写操作。
- 不在第一切片新增独立营销站点、第二套后端编排或破坏既有 REST、SSE、WebSocket 与 `ExecutionEvent` 契约。

## 3. 产品结构

应用保留单一入口，但在顶部切换两个清晰的工作表面，而不是把客户与操作员混在同一组标签里：

```text
智慧园区 Agent 体验中心
  ├─ 客户体验导览（默认表面）
  │   ├─ 导览首页 / 任务选择
  │   ├─ 任务舞台
  │   └─ 证据回顾
  └─ 运营工作台（保留既有能力）
      ├─ 告警工作流
      ├─ 园区客服
      ├─ 专家协作
      ├─ 运营分析
      └─ 实时语音（仅在线能力就绪时）
```

第一实现切片不增加新 URL 或第二个 Vue 应用。`App.vue` 增加表面状态，客户体验导览作为默认表面；运营工作台继续复用现有 `activeView` 和业务组件。未来若需要独立对外站点、认证策略或嵌入式展台，再单独评审路由与部署边界。

## 4. 体验导览主线

### 4.1 一分钟演示节奏

| 时段 | 客户看到什么 | 系统必须证明什么 |
| --- | --- | --- |
| 0–10 秒 | 园区任务、业务影响和本次可用能力 | 当前链路、数据与权限状态已确认 |
| 10–20 秒 | 任务被拆成可理解的 Agent 工作 | 调度的是相关角色，而不是泛化的“AI” |
| 20–45 秒 | 工具查询、专家发现或只读分析结果持续进入证据轨迹 | 所有可见步骤来自真实 `ExecutionEvent` 或已验证结果 |
| 45–60 秒 | 结论、证据范围、人工决策点和下一步 | Agent 没有越权，结果可追溯、可重试、可退出 |

导览一次只聚焦一个任务，不在首屏堆叠所有功能。默认推荐任务由服务端就绪场景决定：跨域专家协作优先展示多 Agent 分工；若不可用，回退到已就绪的告警处置或运营分析。这里的“回退”仅指选择另一项已验证能力，绝不把失败链路改为 Mock 结果。

### 4.2 三类可导览任务

| 场景 | 客户问题 | 主要证明 | 人工边界 |
| --- | --- | --- | --- |
| 告警处置 | “配电或暖通异常该如何处置？” | 告警分诊、上下文查询、知识检索、风险门禁与工单建议 | 高风险处置必须由审批人确认 |
| 专家协作 | “能耗、设备与安防是否存在关联？” | Supervisor 选择领域专家，并行生成带证据的 `ExpertFinding` | 证据不足和部分失败被明确保留 |
| 运营分析 | “过去几天哪座楼能耗偏离基线？” | 指标口径、只读 SQL、安全门禁、结果表和图表 | 无数据或安全拒绝时不生成数字结论 |

语音助手不列为默认任务。只有 ASR、Agent 工具调用和 TTS 的当前在线检查均通过时，它才出现在可选任务中；否则体验导览只显示“本次展台未启用语音链路”的原因和不影响当前演示的其他已就绪任务。

## 5. 屏幕与交互

### 5.1 导览首页

导览首页承担“讲清楚产品价值”而不是“罗列模块”的职责。

- 顶栏：产品名“智慧园区 Agent 体验中心”、当前链路状态、最近检查时间、进入运营工作台入口。角色选择不出现在客户首屏。
- 主叙事：一句业务承诺，例如“让园区决策从信号到证据，再到可控行动”。副文案说明 Agent 只读分析、证据追溯和人工审批原则。
- 中央视觉：使用经过授权或生成的园区数字孪生/认知核心素材，不用 CSS 图形、emoji、占位框或虚假的设备界面代替真实视觉资产。素材承载当前选中任务的园区区域与信号，不承载事实数据本身。
- 任务选择：最多三个已就绪任务，以业务问题、预期时长、可验证证据和人工边界组成紧凑的选择器；只有一个主按钮“开始现场演示”。
- 能力账本：一条简洁的状态行，说明模型、数据、事件流和审批边界；`NOT_READY` 场景可查看原因，但不能点击启动。

### 5.2 任务舞台

任务启动后，页面转为三栏但不成为传统仪表盘：

```text
任务上下文与当前问题 | Agent 决策舞台                         | 证据轨迹
                   | 观察 → 分析 → 建议 / 人工确认           | 真实事件
```

- 左栏“任务上下文”：业务问题、园区区域、可访问的数据范围、剩余演示时长和“结束本次演示”。不显示内部告警编号、供应商名或诊断控制器细节，除非它们是证据引用的安全公开字段。
- 中栏“Agent 决策舞台”：每次只突出当前阶段。告警场景显示风险闸门；协作场景显示 Supervisor 计划与已选择专家；分析场景显示指标口径、查询计划、已验证 SQL、表格和图表。阶段依据现有事件和场景运行 DTO，而不根据前端延时模拟进度。
- 右栏“证据轨迹”：复用 `ExecutionTraceRail` 的事件顺序、运行状态和安全摘要，视觉上从时间线升级为证据卡片流。每张卡只显示角色、阶段、时间、来源类型和安全摘要；可展开的内容只能来自封闭 `displayPayload` DTO。
- 底部“信任条”：持续显示“只读数据”“人工审批”“不展示思维链”三项固定边界；运行期间显示当前状态，终态显示可复盘的结果摘要。

### 5.3 结果回顾与失败状态

成功结束时，任务舞台保留最后有效证据并显示：结论、证据数、已参与 Agent、人工确认状态和下一步建议。客户可以“选择下一项任务”或“返回导览首页”，但不能从结果页直接触发写操作。

失败、超时、中断、证据不足或部分专家失败时，页面必须原位展示真实失败阶段、公开错误码、最近一条有效证据和人工重试按钮。它不清空已经验证的内容，不显示堆栈、供应商响应、Prompt 或未经验证的结论，也不自动切换到离线结果。

## 6. 视觉系统

### 6.1 品牌气质

采用“认知核心”而非通用 SaaS 卡片墙：黑曜石与石墨为基底，光谱青用于已验证数据与实时状态，电光紫用于 Agent 编排层，暖象牙色承载主要文字。体积光、细密网格和留白建立高级感，但不能以霓虹、赛博城市、机器人形象或大量动态特效掩盖信息层级。

### 6.2 令牌与排版

- 页面背景：深石墨，面板使用半透明黑玻璃而非白色卡片堆叠。
- 强调色：仅使用青色、紫色、琥珀色（人工确认）和红色（失败）；颜色同时配合文本和图标，不能单独传达状态。
- 中文正文采用可读无衬线字体；大标题可采用高对比中文衬线搭配，最多两种字体。
- 采用 8px 间距体系，正文不小于 14px，关键信息不小于 16px；所有动效尊重 `prefers-reduced-motion`。
- 圆角、阴影、边框只用于区分层级，避免卡片套卡片。证据轨迹用空间、排版和细分隔线组织，不把每条事件做成独立大卡。

### 6.3 资产原则

当前没有可复用的客户视觉资产。实现前应使用 Image Gen 或经授权的真实素材生成一个与屏幕尺寸匹配的园区认知核心视觉，并在素材可用后做截图对比；不得用手工 SVG、CSS 画图、emoji 或临时占位替代。图片生成服务在本次设计阶段返回 404，因此该资产需要在实现前重新生成并由用户确认。

## 7. 真实能力与数据契约

### 7.1 导览能力目录

现有 `/api/operations/capabilities` 保持兼容，不删除现有字段。新增独立的导览能力目录，或在不破坏消费者的前提下追加字段，向 UI 交付每一个可展示场景的真实状态：

```text
capturedAt
scenarios[]
  id: ALERT_WORKFLOW | EXPERT_COLLABORATION | OPERATIONS_ANALYSIS | VOICE_ASSISTANT
  status: READY | NOT_READY | DISABLED
  live: true
  title
  businessQuestion
  expectedDurationSeconds
  requiredCapabilities[]
  proofTypes[]
  humanBoundary
  unavailableReason
```

- `READY` 的前提是对应功能开关、必要模型/数据库连接和展台健康检查均已通过；不是简单的 Bean 存在。
- `NOT_READY` 必须携带安全、可理解的原因；其任务不可启动。
- `DISABLED` 只说明本次部署未启用，不泄露环境变量或内部拓扑。
- 目录不得返回密钥、内部 URL、原始错误、提示词或未脱敏业务记录。

### 7.2 事件与场景运行

`ExecutionEvent` 仍然是导览轨迹的唯一实时来源。导览层只按 `scenario`、`actor`、`stage`、`eventType`、`status`、`safeSummary` 和封闭 `displayPayload` 投影视觉状态；不扩展任意 Map，也不让前端承担脱敏责任。

现有场景组件继续拥有其运行逻辑：

| 现有资产 | 导览中的职责 | 改造原则 |
| --- | --- | --- |
| `OperationsAnalysisPage` | 指标、计划、SQL、结果与图表 | 用导览外壳收敛输入和布局，保留 `run-started` 订阅 |
| `ExpertCollaborationPage` | Supervisor、专家卡与汇总 | 复用运行与 Finding，导览只改变任务叙事和优先级 |
| `VoiceAssistantPage` | 在线语音会话 | 仅由 `READY` 目录暴露，不能在不可用时渲染假麦克风 |
| 告警工作流、`AlertSelector`、`WorkflowGraph` | 告警选择、风险门禁与人工审批 | 选择器收敛为任务上下文，工作图按当前阶段聚焦 |
| `ExecutionTraceRail` | 统一事件可视化 | 提取为证据轨迹视觉变体，保留序号缺口与失败处理 |
| `DemoConsole` | 内部观测、故障注入与管理指标 | 移入运营工作台，客户导览不展示 |

## 8. 状态、权限与安全

- 客户表面默认是查看模式；人工审批只在告警场景且后端明确要求审批时出现。
- UI 不能根据本地角色选择器假定审批权限，实际操作能力仍由服务端角色和风险门禁决定。
- 所有“在线”“实时”“已验证”文案必须绑定目录状态或实际运行事件；网络未知时显示“正在检查”，不得显示绿色成功状态。
- 工具、SQL 和专家结论只展示服务端已经白名单和脱敏的内容。
- 结束、取消和重试必须走既有会话/运行控制契约；取消后轨迹状态为 `interrupted`，不伪造完成结果。

## 9. 可访问性与响应式要求

- 桌面基准为 1440 × 1024；三栏最小宽度分别为 260px、560px、320px。
- 宽度低于 1250px 时，证据轨迹移至主舞台下方；低于 760px 时，任务上下文折叠为抽屉，阶段和证据保持线性阅读顺序。
- 所有状态有文字标签、非颜色图标和 `aria-live` 摘要；事件流更新不应抢走键盘焦点。
- 任务选择、启动、结束、重试、进入工作台和返回导览可通过键盘完整操作，焦点状态在深色背景上达到可见对比。
- 动态舞台采用有限、可预测的动画；减少动态偏好下只保留状态淡入和顺序更新。

## 10. 交付切片

1. **导览外壳与视觉令牌**：增加客户/工作台表面切换、深色视觉令牌、空态和响应式骨架，不改变业务运行。
2. **导览能力目录**：提供兼容的场景 `READY`、`NOT_READY`、`DISABLED` 状态与安全原因，替代仅凭布尔开关隐藏入口。
3. **任务选择与能力账本**：实现导览首页、真实就绪场景选择和无能力状态，拒绝 Mock 冒充在线演示。
4. **证据轨迹适配**：将 `ExecutionTraceRail` 投影为证据轨迹，复用 `ExecutionEvent` 的顺序、终态和错误语义。
5. **三类任务舞台**：逐个用外壳接入告警、专家协作与运营分析，不复制编排逻辑；语音作为独立受门禁切片。
6. **结果与人工边界**：接入成功、部分失败、超时、中断、审批和可复盘结果。
7. **视觉资产与验收硬化**：生成并确认园区认知核心资产，完成截图比较、可访问性、浏览器流程和在线验收。

每个切片独立提交和验证。任何真实链路失败均保留原位失败状态；不通过前端降级取得演示“成功”。

## 11. 验证策略与验收标准

### 11.1 自动化验证

- Vue 单测覆盖目录状态、任务选择、无就绪任务、事件顺序、失败和中断展示、键盘操作与减少动画。
- Playwright 覆盖：客户首次进入、只显示 `READY` 任务、启动后订阅真实运行 ID、部分专家失败、分析需澄清、审批边界和返回工作台。
- 导览 UI 测试使用测试替身只验证呈现与交互；测试报告必须明确它不等同于在线 Agent 验收。
- 后端契约测试验证目录不会把 `NOT_READY` 标为在线、`unavailableReason` 不泄露敏感信息、既有 capabilities 消费者保持兼容。

### 11.2 在线验收

- 展示前显式运行每个候选场景的在线 Smoke；只有成功的场景进入 `READY`。
- 至少完成一次跨域协作或运营分析的真实全链路，并确认轨迹、证据和结论一致。
- 告警场景必须在需要时停止于人工审批；不允许自动越过风险门禁。
- 语音仅在 ASR、工具调用与 TTS 都实际成功后展示；失败时报告真实阶段。

### 11.3 基线记录

本规格创建时，前端 `test:unit` 为 78/78 通过。后端全量测试为 772 通过、3 跳过、1 失败：`ReadOnlyQueryExecutorTest.executesWhitelistedQueriesWithBoundParameters` 固定查询 2026-08-20 至 2026-08-25，而分析迁移按 `CURRENT_DATE` 生成最近数据，导致 2026-08-30 的运行返回 0 行。该时间漂移是既有测试夹具问题，不属于本 UI 切片；修复应另开小切片，以数据库相对日期构造断言或测试数据。

## 12. 评审结论

本设计把客户价值集中在“可信的 Agent 执行证据”，把内部操作复杂度留在运营工作台。它复用现有 Vue 场景、`ExecutionEvent`、风险门禁和只读分析边界，同时补上客户演示所缺的能力目录、任务叙事和真实状态表达。规格获批后，下一步是拆分第一切片的实施计划，而不是直接重写所有现有页面。
