# 全场景演示：实时语音与告警处置能力设计

- 状态：已确认，待实施
- 日期：2026-08-31
- 范围：在现有沉浸式工作台 PR 中启用并在线验证实时语音、告警处置、专家协同和运营分析四类演示能力

## 背景与根因

当前首页会依据 `/api/operations/capabilities` 和最近一次现场预检结果决定场景是否可进入。现有 Docker 分析覆盖层只启用了 DashScope 与运营分析，没有同时打开知识库 RAG、客服在线回答和实时语音，因此告警处置与语音助手会显示为 `DISABLED`。即使仅补齐环境变量，首页仍会因为缺少最近一次成功的在线预检凭据而显示 `NOT_READY`。

现有未提交的预检原型只验证专家协同和运营分析，并且由一个中央服务直接依赖各业务子系统。继续在该服务内堆叠语音和告警依赖，会把演示编排层变成新的业务耦合中心，也无法清晰表达告警预检禁止创建工单、语音预检不等于浏览器麦克风验收等边界。

本设计从根因上同时解决三个问题：

1. 用场景自有探针证明能力真实可用，而不是把“配置已打开”误报为“现场可演示”。
2. 用独立、可叠加的 Compose 覆盖层启用完整在线能力，同时保持默认离线启动无密钥、可复现。
3. 把告警写操作和浏览器麦克风等高风险或客户端边界明确隔离，避免预检产生业务副作用或夸大验证范围。

## 目标

- 一条明确的 Docker 命令启动四类完整在线演示能力。
- 管理员执行一次预检后，四个场景都获得有时效的 `READY` 凭据，首页可以进入对应演示。
- 告警预检真实经过 RAG、DashScope Agent 和 Graph 路由，并停在人工审批节点，不创建工单。
- 语音预检真实验证 ASR、回答 Agent 和 TTS 服务端链路；浏览器 WebSocket、麦克风权限和真实语音往返另做现场验收。
- 预检响应和日志不泄露密钥、原始音频、模型内部信息或供应商错误详情。
- 默认 Compose 行为、离线测试和无密钥开发流程保持不变。
- 选择性吸收主工作区中与预检相关的原型，不带入 JioNlp、协同服务等无关未提交改动。

## 非目标

- 不用预检替代浏览器麦克风授权、声卡设备和网络质量验收。
- 不在告警预检中自动批准、创建或持久化真实工单。
- 不把 API 密钥、供应商响应或测试音频写入仓库。
- 不重做已有的 ASR、TTS、RAG、Graph 或 Agent 实现；探针复用项目现有端口和业务流程。
- 不改变默认离线演示的能力门禁。

## 方案选择

采用“场景自有探针 + 通用预检协调器 + 独立全场景 Compose 覆盖层”。

没有选择中央服务直接依赖全部业务实现，因为该方案会随场景增长持续增加耦合，且场景特有的安全边界难以测试。没有选择只修改环境变量，因为它只能证明配置存在，无法证明模型、RAG、Graph、ASR 和 TTS 的在线链路可用，也无法生成首页需要的成功预检凭据。

## 总体架构

### 场景探针契约

新增轻量的 `ShowcasePreflightProbe` 扩展点。每个已启用场景提供自己的探针 Bean，负责调用该场景现有的业务端口并把结果归一化为内部探针结果。

契约至少包含：

```java
public interface ShowcasePreflightProbe {
    ShowcaseScenarioId scenarioId();
    ShowcaseProbeResult probe();
}
```

`ShowcaseProbeResult` 只表达成功或安全的失败原因，不携带原始供应商响应。探针 Bean 使用既有能力开关条件注册；没有启用的场景不注册探针，也不会被默认离线环境误调用。

### 通用预检协调器

`ShowcasePreflightService` 只依赖探针集合、场景目录和预检凭据存储，不直接依赖语音、告警、协同或分析服务。它按固定的 `ShowcaseScenarioId` 顺序运行已注册探针，并负责：

- 管理员单次触发和进程内 single-flight，避免同一实例并发消耗模型与语音资源。
- 对每个探针施加统一、可配置且必须为正数的超时，默认 90 秒。
- 成功时写入该场景的最近验证时间；失败、超时或异常时立即清除旧凭据，防止旧 `READY` 掩盖当前故障。
- 将异常记录为服务端受控日志，只保留场景 ID 与异常类型；外部响应统一返回“在线验证未通过”。
- 生成带 `verifiedAt` 的场景结果，不返回堆栈、模型名、供应商错误正文或密钥信息。

成功凭据有效期保持 15 分钟。应用重启后凭据不恢复，现场演示前需要重新运行预检，这是刻意的安全设计，避免把历史在线状态当成当前状态。

### 完整性防线

协调器可以运行当前部署中已注册的探针，但完整演示校验脚本必须断言结果恰好覆盖以下四个场景 ID，并且全部为 `READY`：

- `ALERT_WORKFLOW`
- `EXPERT_COLLABORATION`
- `OPERATIONS_ANALYSIS`
- `VOICE_ASSISTANT`

这样即使某个条件 Bean 因配置错误没有注册，脚本也会失败，而不会因“所有返回项都成功”产生假绿。

## 四类探针

### 专家协同

复用现有协同服务执行一次受控演练，要求流程成功结束且返回非空发现结果。探针不修改协同业务实现，不引入新的模拟实现。异常和空结果均判定失败。

### 运营分析

复用现有分析服务运行已知可用的受控查询，要求任务完成且 `rowCount > 0`。它同时验证数据源、分析编排和结果映射，不仅检查健康端点。

### 告警处置

告警探针必须验证真实 RAG、DashScope Agent 和 Graph 路由，同时绝不触碰正常演示的工单写路径。

实现方式：

1. 使用固定、高风险且可重复的演示告警输入，例如已有的 `ALT-POWER-001` 夹具。
2. 为每次预检创建独立的 `AlertWorkflow` 实例，注入临时 `WorkflowExecutionStore`，绕开正常流程的去重记录，确保每次预检都是新鲜执行。
3. 注入预检专用的隔离发布器和拒写 `WorkOrderPort`。任何创建或更新工单的调用都立即使探针失败。
4. 仍复用生产 RAG 检索、在线 Agent 和 Graph 定义，让执行真实到达人工审批边界。
5. 只有当最终快照处于 `WAITING_APPROVAL`、诊断非空、错误为空且没有工单时才成功。

探针不得调用批准接口，也不得用普通生产存储运行后再清理。拒写边界和临时存储从结构上保证“没有副作用”，而不是依赖事后补偿。

### 实时语音

语音探针分三段复用项目现有端口，并明确其验证边界：

1. ASR：创建唯一 session/turn，发送有上限的 16 kHz 单声道静音 PCM 后提交，等待干净的终态回调；供应商错误、超时或非法状态均失败。该步骤证明流式供应商连接和会话状态机可用，不宣称识别准确率。
2. Agent：向现有 `VoiceAnswerAgent` 提交确定性文本问题，要求回答通过现有校验并且正文非空；需要工具或证据的既有约束继续生效。
3. TTS：合成上一步已校验回答，要求在超时前收到至少一个非空 PCM 数据块并正常完成。

无论成功或失败，探针都必须取消并清理活动 turn，清零或丢弃临时音频缓冲区。对外结果和日志不得包含原始音频、转写正文、完整回答或供应商错误正文。

服务端预检不模拟浏览器麦克风。现场验收另行确认浏览器 WebSocket、麦克风权限、录音发送和音频播放，以免把服务端连通性错误表述为端到端硬件验证。

## API 与安全

保留管理端预检入口：

```http
POST /api/showcase/preflight
X-Demo-Role: ADMIN
```

非管理员返回拒绝访问。成功响应只包含场景 ID、`READY`/`NOT_READY`、安全原因和 `verifiedAt`。接口不接收或返回密钥，不允许客户端选择跳过探针，也不暴露底层供应商错误。

首页继续通过现有能力目录与有时效预检凭据计算状态。能力开关关闭时为 `DISABLED`；能力已启用但没有新鲜成功凭据时为 `NOT_READY`；两者都满足时才为 `READY`。

## Compose 与密钥策略

新增 `compose.showcase.yaml`，作为 `compose.yaml` 和 `compose.analytics.yaml` 之上的可选覆盖层。完整演示使用：

```powershell
docker compose --env-file .env `
  -f compose.yaml `
  -f compose.analytics.yaml `
  -f compose.showcase.yaml `
  --profile analytics up --build
```

覆盖层为后端增加：

- `SMARTPARK_KNOWLEDGE_MODE=rag`
- `SMARTPARK_CUSTOMER_SERVICE_ANSWER_MODE=dashscope`
- `SMARTPARK_VOICE_ENABLED=true`
- `SMARTPARK_VOICE_ALLOWED_ORIGINS` 默认允许 `http://localhost:5173,http://127.0.0.1:5173`

DashScope 在线能力和密钥映射继续由分析覆盖层与 `.env` 提供。仓库只跟踪变量引用，不跟踪密钥值。完整演示缺少所需密钥时必须在启动或预检阶段明确失败，不静默降级成假在线；默认 Compose 不叠加该覆盖层时维持无密钥离线行为。

## 校验脚本

将 `scripts/verify-showcase.ps1` 纳入分支。脚本使用管理员角色调用预检接口，并进行结构化 JSON 校验：

- HTTP 请求成功。
- 四个预期场景 ID 全部存在且没有额外或重复 ID。
- 四个结果全部为 `READY`。
- 每项都有合法的 `verifiedAt`。

任一条件不满足时返回非零退出码，并只输出安全、可操作的场景级摘要。脚本不得解析页面文案来判断能力状态。

## 错误处理与可观测性

- 探针失败只影响对应场景，不阻止协调器收集其他场景结果。
- 任何失败都清除该场景旧凭据。
- 超时由协调器统一控制，探针内部仍需在 `finally` 中释放资源。
- 日志记录请求关联 ID、场景 ID、耗时和异常类型；不记录密钥、原始音频、完整提示词、转写或模型输出。
- 前端展示安全原因和重新预检入口，不把供应商详情直接暴露给演示用户。

## 测试策略

实施遵循测试驱动开发，每个行为先写失败测试，再增加最小实现。

### 单元与切片测试

- 协调器：固定顺序、单场景失败不中断、异常屏蔽、超时、成功写凭据、失败清旧凭据、缺少探针不会被误判成功。
- 告警探针：真实流程到达 `WAITING_APPROVAL` 才成功；诊断为空、Graph 错误、非审批终态或任何工单写尝试都失败；临时存储不污染生产状态。
- 语音探针：ASR 错误与超时、Agent 空回答或失败、TTS 零字节或未完成都失败；成功和失败路径均执行取消与缓冲清理。
- 协同与分析探针：分别验证空发现、未完成任务和零行结果的失败行为。
- Controller：管理员可运行，其他角色拒绝；响应不泄露内部异常。
- 配置：预检超时与凭据 TTL 必须为正数，能力条件按预期注册探针。

### 架构与集成测试

- Compose 契约测试解析合并后的配置，验证全场景环境变量、双本地 Origin、密钥只以变量引用出现，默认 Compose 未被改变。
- 脚本在受控响应下验证缺场景、重复场景、非 READY 和非法时间戳都会非零退出。
- Maven 测试继续默认离线；在线供应商测试只在显式启用时运行。
- 前端测试覆盖首页四状态、预检失败提示，以及语音入口在 READY 后可进入。

### 完整验收

1. 运行后端全量 Maven 测试、前端单元测试、构建和现有布局校验。
2. 使用三层 Compose 命令重新构建并启动容器，确认健康检查通过。
3. 运行 `scripts/verify-showcase.ps1`，确认四个场景全部 `READY`。
4. 在浏览器首页逐个进入四种现场演示。
5. 告警演示确认停在人工审批，预检前后无新增工单。
6. 语音演示手工授权麦克风，完成一次真实说话、转写、回答和播放往返。

## 实施与迁移边界

主工作区现有未提交预检原型只能作为行为参考。实施时在功能分支按本设计和测试重新整理为场景探针，不复制无关的 JioNlp、协同服务或其他并行改动。功能工作树中当前存在的并行 UI 变更也保持独立，只有确认属于本能力并通过测试的改动才进入后续实现提交。

## 验收标准

- `/api/operations/capabilities` 显示语音启用、知识模式为 RAG、客服回答模式为 DashScope。
- 管理员预检返回四个且仅四个预期场景，全部为 `READY`。
- 首页四个场景均可选且进入正确的差异化演示流程。
- 告警探针真实经过在线推理并停在 `WAITING_APPROVAL`，没有创建工单或污染正常流程状态。
- 语音探针通过 ASR、Agent、TTS 三段在线验证；浏览器完成一次人工麦克风端到端验收。
- 默认离线 Compose 和离线测试无需密钥即可继续运行。
- 仓库、接口响应和日志均不出现密钥、原始音频或供应商内部错误详情。

## 已知运行约束

- `READY` 凭据有效期为 15 分钟，应用重启或凭据过期后需重新预检。
- 服务端语音预检不能证明用户浏览器已授权麦克风，也不能代替现场声卡和网络环境检查。
- 全场景模式会产生真实模型和语音调用费用，因此仅通过显式 Compose 覆盖层启用。
