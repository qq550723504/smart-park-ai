# 协同中心 SLA 会话趋势设计

**状态：** 已确认设计，待实施计划评审

## 1. 目标

在现有只读协同中心中增加真实的 SLA 会话趋势：服务端按协同队列读取采样，前端以趋势图展示“已超时、即将到期、正常”的状态数量。趋势只反映当前服务进程内采集到的数据，不伪造历史，也不改变告警工作流和客服工单的写入边界。

## 2. 范围与非目标

### 范围

- 为完整的未筛选协同队列生成 SLA 状态快照。
- 提供受角色保护的只读趋势接口。
- 在协同中心展示会话采样趋势图、采样点数量和明确的空态/错误态。
- 保持来源筛选、状态筛选、SLA 排序、最近更新时间排序、自动刷新、详情抽屉和原场景跳转行为不变。

### 非目标

- 不新增数据库、数据库迁移或跨实例共享存储。
- 不把协同快照写入 analytics 数据库。
- 不为告警或客服领域模型增加历史字段，也不新增审批、派单、设备控制等写操作。
- 不把当前队列推断成服务启动前的历史数据。

## 3. 架构

### 3.1 快照模型

新增应用层记录 `CollaborationSlaSnapshot`，字段为：

- `Instant capturedAt`
- `int total`
- `int overdue`
- `int dueSoon`
- `int onTrack`
- `int completed`
- `int notApplicable`

快照只包含状态数量，不携带工作项标题、位置、设备或安全摘要，避免趋势接口扩大数据暴露面。

### 3.2 会话快照仓

新增 `CollaborationSlaSnapshotStore`，负责：

- 线程安全地追加快照并返回不可变副本。
- 在相邻采样时间小于 30 秒时跳过重复采样。
- 最多保留最近 120 个快照，约覆盖 1 小时的 30 秒采样窗口。
- 支持按 `limit` 返回最近点，接口上限为 120。
- 服务重启后自然清空；响应和 UI 均标注“本次会话采样”。

### 3.3 采样时机与队列边界

`CollaborationCenterService` 在生成当前完整队列后、应用 `source`/`status`/`sort`/`limit` 查询条件前调用快照仓。这样无论用户当前选择何种筛选和排序，趋势都代表完整的协同队列。只有协同队列读取触发采样；现有前端 30 秒刷新会持续产生采样点，页面不访问时不产生后台伪数据。

## 4. HTTP 契约

新增：

```text
GET /api/collaboration/sla-trend?limit=60
X-Demo-Role: CUSTOMER_AGENT | ADMIN
```

响应按时间升序返回：

```json
[
  {
    "capturedAt": "2026-09-02T10:00:00Z",
    "total": 4,
    "overdue": 1,
    "dueSoon": 1,
    "onTrack": 2,
    "completed": 0,
    "notApplicable": 0
  }
]
```

`limit` 默认 60，允许范围为 1–120；非法值返回 400。普通查看者继续收到协同中心的无权限响应，且前端不发起趋势请求。

## 5. 前端交互

新增 `CollaborationSlaTrendChart` 组件，复用现有 `AnalyticsChart` 使用的 ECharts 和 `withDarkTheme` 主题装饰能力。组件只接收后端快照数组，将 `capturedAt` 映射为时间轴，将 `overdue`、`dueSoon`、`onTrack` 映射为三条折线。

趋势面板包含：

- 标题“本次会话 SLA 趋势”。
- “已采样 N 个点 · 最多 120 点”状态说明。
- 无点时的“正在采样”空态，不绘制默认点。
- 趋势接口失败时的独立错误提示；队列仍保持可用。

协同中心初次读取队列后读取趋势，后台刷新继续保留已显示的队列和趋势，只有成功获得新数据才替换对应状态。角色切换为不可读、页面 inactive 或队列初次读取失败时，清理趋势并停止请求。

## 6. 错误处理与安全

- 快照仓容量、采样间隔和 limit 均在应用层强制限制，不信任客户端参数。
- 趋势接口只返回聚合数量和时间，不返回受保护工作项详情。
- 趋势采样失败不阻断现有工作项列表；列表失败也不显示旧趋势为最新状态。
- 所有角色校验复用 `DemoRole.require`，不创建新的身份体系。

## 7. 测试策略

### 后端

- 快照计数正确聚合五种 SLA 状态。
- 30 秒采样窗口内去重，超过窗口可追加。
- 超过 120 点时淘汰最旧点，读取结果不可变且按时间升序。
- 协同服务在筛选前采样完整队列。
- 趋势接口验证默认/边界 limit、非法 limit 和角色权限。

### 前端

- API 客户端序列化 limit 和角色请求头。
- 趋势图生成三条折线并正确设置时间轴；空数组不创建伪造点。
- 协同中心展示趋势、采样数量、空态和独立错误态。
- 后台刷新保留旧趋势，成功响应后更新；无权限和 inactive 时不请求。
- 现有协同中心、分析图表和工作台测试继续通过。

## 8. 生产化迁移路径

若后续需要重启保留、跨实例一致或按园区/团队查询历史，应另行设计持久化快照表、采样调度、保留策略、索引、权限和监控。届时可保持 `CollaborationSlaSnapshot` 和趋势 DTO 的字段契约，将内存仓替换为持久化适配器；本阶段不预埋数据库依赖。
