# 智慧园区 AI 能力展示

## 1. 项目概览

智慧园区 AI 运营中心面向园区运营、设备管理、客服服务和管理决策场景，把分散的告警、能耗、设备、知识和服务流程组织成可追踪的智能工作流。

系统的核心价值不是“只给出一个 AI 答案”，而是让每一次回答都能看到：系统理解了什么、查了哪些数据、为什么采取这条路径、何时需要人工确认，以及最终结果如何继续执行。

## 2. 客户可体验的核心能力

### 2.1 告警智能处置

从一条园区告警开始，系统自动完成：

1. 判断告警类型、优先级和风险等级。
2. 读取关联设备状态、历史告警和已有工单。
3. 检索对应的园区处置知识。
4. 形成结构化诊断和处置建议。
5. 根据风险和证据决定自动推进，或暂停等待人工审批。
6. 审批通过后创建可追踪的处置工单。

高风险、低置信度或缺少知识依据时，系统不会直接执行下一步，而是把需要人工确认的原因展示出来。适合演示温度、电力、能耗和门禁安防等异常场景。

### 2.2 自然语言运营分析

运营人员可以直接提出业务问题，例如：

- “上周各楼宇能耗对比如何？”
- “最近几天高风险告警有多少？”
- “哪些停车区域的利用率接近容量上限？”

系统会把问题转换为统一指标和维度，必要时先询问指标口径，再生成查询计划、校验 SQL、检查执行成本，最后返回数据表、图表和结论。

该能力的特点是：

- 面向业务人员使用自然语言，不要求先写 SQL。
- 只访问专用分析数据和白名单视图。
- 查询过程和安全校验过程可见。
- 查询失败或结果不足时明确反馈，不用无依据的内容替代。

启用分析模式后，数据来自独立 PostgreSQL 分析数据库；本地 analytics 演示覆盖配置提供预置分析数据。

### 2.3 多专家协作分析

面对同时涉及能耗、设备和安防的复杂问题，系统由主管先判断需要哪些领域专家，再并行组织分析：

- 能耗专家：查看能耗读数、基线和峰值情况。
- 设备专家：查看设备状态、关联告警和已有处置信息。
- 安防专家：查看脱敏安全事件和访问风险。

每位专家只处理分配给自己的领域，并且必须引用真实查询证据。主管汇总时会展示参与了哪些专家、返回了哪些结论、哪些证据支撑了结论，以及还存在哪些不确定性。

### 2.4 园区智能客服

园区访客或员工可以咨询停车收费、访客预约、公共区域能耗等常见问题。系统基于园区知识回答，并展示引用的知识来源。

对于“洗手间漏水”“空调故障”等报修问题，系统会确认报修意图并创建人工客服工单；对于知识不足或策略不允许自动回答的问题，系统会有序转人工，不生成泛化答案。

客服支持多轮会话、人工工单队列和工单状态推进，方便展示“自动服务—人工接管—持续跟踪”的完整闭环。

### 2.5 园区知识管理

知识可以按“客服”和“告警运维”两个领域管理：

- 查看知识文档元数据和启用状态。
- 新增园区规则、操作手册和服务说明。
- 启用或停用文档，立即影响后续检索。
- 通过关键词检索或进程内向量检索匹配知识。

知识正文不会通过管理元数据接口或外部只读 MCP 工具直接暴露，便于后续接入更严格的知识权限和版本治理。

### 2.6 全过程可追踪与人工参与

告警、专家协作和运营分析共享统一的执行轨迹。用户可以看到运行编号、当前阶段、工具调用、专家交接、SQL 校验、结果生成和最终状态。客服当前通过会话消息和人工工单状态展示进展，尚未接入这条统一执行事件流。

系统把“自动执行”和“人工决定”明确分开：

- 高风险告警可以暂停等待审批。
- 审批意见和操作动作进入审计记录。
- 诊断和服务结果可以提交正确/不正确反馈。
- 失败节点和安全摘要可供运营人员定位问题。

## 3. 典型展示路径

### 场景 A：高风险能耗异常

选择能耗告警后，展示告警分诊、设备与历史数据、能耗基线、知识检索和 AI 诊断。当系统判断风险高或证据不足时，界面进入“待人工审批”，审批人确认后再创建处置工单。

客户可以直观看到：AI 负责分析和建议，关键动作由风险门禁和人工确认共同控制。

### 场景 B：一句话运营分析

进入“运营分析”，输入“各楼宇能耗对比”。系统展示问题理解、指标选择、查询计划、SQL 安全校验、只读查询结果和图表。若问题中的“告警”存在多个指标含义，系统会先要求选择“告警数量”或“高风险告警数量”。

客户可以直观看到：自然语言入口背后仍有指标口径、数据权限和 SQL 安全约束。

### 场景 C：复杂问题专家会诊

输入“电表 DEV-ENERGY-001 当前能耗是否高于基线，设备是否存在关联告警”。系统选择能耗和设备专家，两个分支并行查询并返回证据，主管再汇总形成结论。

客户可以直观看到：复杂问题不是由一个通用提示词包办，而是由领域专家分工协作完成。

### 场景 D：客服自动回答与转人工

先咨询“访客停车怎么收费？”，系统返回知识引用；再输入“A1 洗手间漏水，需要报修”，系统创建人工客服工单，并在客服队列中显示待接入状态。

客户可以直观看到：常见问题自动响应，确定的服务请求进入人工闭环。

## 5. 安全与治理特点

- 高风险或证据不足的处置默认转人工，不直接创建工单。
- Agent 只使用只读查询工具，写入动作由工作流控制。
- 安防链路只使用脱敏摘要，不把原始视频、图片或人员身份数据送入通用模型流程。
- 运营分析使用独立数据库和只读角色，并对 SQL 做 AST、查询计划、参数、成本和结果边界校验。
- 客服回答带知识来源；知识不足时转人工或返回受控结果。
- 对外接口和执行事件默认只展示流程信息与安全摘要，不展示诊断、审批或知识正文。
- MCP 默认关闭，启用后也只提供告警、能耗和知识元数据的只读查询。

## 6. 当前演示边界与落地准备

当前版本适合方案演示、技术验证和流程原型，不应直接作为生产控制系统。正式落地前需要根据客户现有系统完成以下接入：

- 告警、设备、能耗、安防和工单平台的真实适配器。
- 持久化工作流状态、会话、工单、事件和知识索引。
- 跨实例幂等、任务恢复、消息重放和运行监控。
- 企业身份认证、细粒度权限、租户隔离和密钥管理。
- 安防数据的专用访问控制、脱敏和合规审计。
- 分析数据模型、指标目录和客户内部数据权限的确认。

这些工作不会改变当前的核心业务分层：客户系统接入端口，AI 负责理解/分析，工作流负责状态和副作用，统一事件层负责过程可见性。

## 7. 建议的客户验收关注点

客户演示或 PoC 评审可以重点观察：

1. 一条高风险告警是否能够停在人工审批，而不是直接生成处置动作。
2. 运营分析是否能说明指标口径、查询范围和只读安全校验结果。
3. 专家协作是否展示真实分工、证据引用和不确定性。
4. 客服知识不足或报修时是否正确转人工。
5. 接入统一执行轨迹的链路是否有统一运行编号、阶段状态和失败反馈；客服链路是否能通过会话编号和工单状态追踪。
6. 所有“当前能力”和“后续生产化工作”是否被清晰区分。
